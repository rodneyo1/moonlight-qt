# Experimental calibrated frozen keyboard path (protocol v2)

This opt-in Windows implementation connects Moonlight's pre-SDL-enqueue keyboard capture to Sunshine's bounded Windows scheduler and selected libvirtualhid backend. Ordinary input remains the default. This source is undergoing adapter/build verification; it is not a qualified STEADY release.

- Private authenticated control type `0x5355`, capability `x-steady-input.keyboardVersion:2`, fixed 64-byte frames. No new socket or driver.
- HELLO / HELLO_ACK exchange identities and the declared reserve. Fresh unsequenced calibration retains every attempt, with at least 10000 usable replies over at least 30 seconds. REPORT and SEALED freeze the inventory; both endpoints independently compute and compare an immutable rational rate, anchors, uncertainty and finite expiry before OFFER / COMMIT / READY.
- A key before commitment selects legacy for that connection. Unsupported peers, capture capability, keyboard configuration, clock bounds or reserve envelope decline timed ownership. After commitment faults terminate the session and attempt held-key cleanup; input is never replayed through legacy.
- QPC stamps are taken in the SDL2 event filter before SDL enqueue and passed through bounded single-use tokens. This is not physical actuation, HID creation time or a measurement of delay before the filter. Missing, stale or forged original timestamps cannot be replaced with callback time after commitment.
- The causal affine clock model is a stated condition. No symmetric-delay assumption is used. Clock uncertainty determines validity; suspend/resume, identity, frequency and monotonic guards invalidate continuity. Expiry closes the stream rather than silently refitting. A maximum two-hour resource cap does not mean measurements support two hours.
- The declared fixed reserve is 15 ms CLEAN (default) or 25 ms STANDARD (`STEADY_INPUT_PROFILE=standard`). No slew, adaptive buffering or rebuffering. A1 admission constrains the selected map's interval distortion independently of uncertainty in the clock estimate.
- Reliable ordered keyboard-channel transport remains experimental. Application ACK/retry/history/state recovery from the reference core is not yet bound to this transport. Unsequenced calibration does not qualify reliable-channel head-of-line delays.
- Physical USB keyboard profile; custom host remaps and Right-Alt-to-Win decline activation. Owner-thread repeat wiring passes the actual adapter checks; native application/live verification remains open. Complete shortcut/Unicode behavior parity is still open; Unicode injection is currently excluded during timed ownership. Mouse, video and audio use their ordinary paths.
- Fixed inventory, ingress, pending, replay and trace capacities; faults and overflow remain visible. Native cleanup failure is reported.

Launch both apps with process environment `STEADY_INPUT_ENABLE=1` and `STEADY_INPUT_TRACE` set to a new writable CSV filename. Existing installed packages do not acquire new source changes until rebuilt and replaced. Traces are written at teardown without overwriting existing files. Client and host append `.calibration.csv` for the complete calibration inventory and fit metadata. Wait for the calibrated-active log before a timed workload; keyboard input during startup calibration selects legacy.

Client traces retain original capture and callback times, state, source identity and failed submissions. Host traces retain receipts, frozen deadlines, receiver dispatch observations and QPC samples immediately before backend entry, as well as API-return times. Original source identity is preserved; repeats and disconnect cleanup are separate. The dispatch observation includes receiver work after timer wake and is not an independent timer-wake timestamp. Preserve raw traces and all-original denominators. These files alone do not establish browser-level timing acceptance. The historical v1 analyzer must not be used to label v2 results as accepted.

The common-C patch targets pinned commit `04053843c90c4268583f2496b997d54d59f03957`. Shared protocol and calibration headers must be byte-identical in both forks. Full builds, real-network behavior/compatibility, controlled impairment, CPU stress and continuous soak remain required before release.
